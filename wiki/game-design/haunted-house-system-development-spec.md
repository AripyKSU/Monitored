## Overview

이 문서는 폐건물 탈출 공포 게임의 현재 구현 기준을 시스템별로 정의한다. 폐기된 간접 지휘 방식과 관찰·발견·공포 수치 시스템은 사용하지 않는다. 핵심 흐름은 화면의 대상을 클릭하면 접근 지점으로 이동한 뒤 대상 행동을 실행하고, 고정 경로를 순찰하는 적의 접근 경보에 대응해 은신하는 것이다.

## 공통 구현 원칙

- 월드 구조, 방 연결, 적 경로는 기획에서 지정한 고정 데이터로 구성한다.
- 시스템은 현재 필요한 규모만 구현하고 범용 퍼즐 프레임워크나 복잡한 AI 의사결정 계층을 미리 만들지 않는다.
- 정상 플레이에서 도달 불가능한 목적지나 이동 중 대상 비활성화는 런타임 분기가 아니라 스테이지 검증 오류로 취급한다.
- 기존 `Assets/_3DStealthGame/Legacy` 코드는 현재 기획과 무관하므로 구현 기준이나 참고 자료로 사용하지 않는다.

### 기존 코드 마이그레이션 주의

- `Assets/_3DStealthGame/Scripts/RoomTransition.cs`는 삭제된 Legacy 타입에 의존하므로 현행 구현으로 간주하지 않는다. 2번 방·문·CCTV와 3번 `TargetCommand`가 구현될 때 새 흐름으로 교체한다.
- `Assets/_3DStealthGame/Editor/Stage1NavigationSetup.cs`도 삭제된 Legacy 타입을 생성하는 이전 스테이지 설정 도구이므로 사용하지 않는다. 새 스테이지 구성 방식이 정해질 때 교체하거나 삭제한다.
- 위 두 파일을 정리하기 전까지는 삭제된 타입 참조로 Unity 컴파일 오류가 발생할 수 있다.

## 1. 스토리 진행 Core와 체크포인트

### 책임

- 현재 스토리 진행 단계와 일회성 이벤트 실행 여부를 관리한다.
- 방 진입, 아이템 획득, 퍼즐 완료 등의 이벤트를 받아 스토리 이벤트를 실행한다.
- 체크포인트 진입 시 사전에 정의된 부활 상태를 메모리에 기록한다.
- 사망 시 체크포인트 상태로 게임을 복원한다.
- 인벤토리, 대화, 스토리 연출에서 함께 사용할 수 있는 공용 일시정지 기능을 제공한다.

### 확정 사양

- 저장 범위는 현재 실행 세션뿐이다. 디스크 저장과 이어하기는 구현하지 않는다.
- 체크포인트는 임의의 현재 월드 상태를 전부 복제하지 않는다. 스토리 및 맵 기획에서 지정한 부활 위치, 보유 아이템, 퍼즐과 진행 상태를 사용한다.
- 부활 시 적은 체크포인트에 지정된 초기 위치와 순찰 상태로 초기화한다.
- 이미 본 대화를 반복하지 않도록 대화 이후에 체크포인트를 배치한다.
- 평상시 플레이를 나타내는 `Exploration` 전역 상태는 두지 않는다.
- 추격 상태는 이 Core가 아니라 은신·포획·추격 시스템이 소유한다.

### 후속 기획

- 체크포인트 위치와 각 체크포인트의 정확한 부활 상태
- 체크포인트별 활성 스토리 이벤트와 적 배치
- 일시정지 중 허용할 UI와 입력 범위

## 2. 방·문·CCTV

### 책임

- 방 ID, 방 사이의 고정 연결, 문, 방별 CCTV를 관리한다.
- 플레이어와 적의 현재 방 및 문 통과 시점을 알린다.
- 방 전환 시 해당 방의 CCTV로 카메라를 전환한다.
- 위험 경보가 사용할 직접 인접 방 정보를 제공한다.

### 확정 사양

- 방 하나당 CCTV 카메라 한 대를 사용한다.
- 복도도 하나의 방으로 취급한다.
- 인접 방은 문 하나로 직접 연결된 방이다.
- 플레이어가 문을 통과하기 시작하는 시점에 다음 방 CCTV로 전환한다.
- 플레이어는 현재 화면에 표시된 클릭 가능 대상만 선택하므로 카메라 범위 밖의 자유 이동을 지원하지 않는다.
- 방과 문 연결은 런타임에 바뀌는 그래프가 아니라 맵 기획에서 정한 고정 데이터다.
- 잠긴 문이 열리는 것은 연결 구조 변경이 아니라 해당 문의 잠금·사용 상태 변경이다.

### 후속 기획

- 방과 복도의 실제 ID 및 연결 목록
- 문 통과 시작을 판정할 정확한 Transform 또는 Trigger 위치
- 각 CCTV의 배치와 구도

## 3. TargetCommand

### 책임

하나의 클릭 입력을 대상 접근과 도착 후 행동으로 이어지는 단일 명령으로 실행한다.

```text
대상 클릭
→ 클릭 대상 UI 숨김 및 추가 입력 차단
→ 대상의 접근 지점으로 이동
→ 도착
→ 대상 행동 실행
→ 명령 완료
→ 클릭 대상 UI 복구
```

### 확정 사양

- `Move`, `Interact`, `Hide`를 플레이어가 선택하는 별도 명령으로 나누지 않는다.
- 모든 일반 클릭 명령은 하나의 `TargetCommand` 흐름을 사용한다.
- 대상은 접근 지점과 도착 후 실행할 행동을 제공한다.
- 명령 수행 중에는 다른 대상 클릭을 받지 않고 클릭 가능 지점 UI를 숨긴다.
- 도착 후 아이템 획득, 메시지 표시와 같은 기본 행동은 거의 즉시 시작한다.
- 이동과 상호작용 중에도 위험 경보 UI는 화면 중앙 상단에 유지한다.
- 도달 실패와 이동 중 대상 비활성화는 정상 게임 분기가 아니라 스테이지 오류로 기록한다.

### 미확정

- 추격 중 현재 이동을 유지하면서 다음 대상을 예약할지, 즉시 목표를 바꿀지

## 4. 오브젝트 상호작용

### 책임

`TargetCommand`가 대상에 도착했을 때 오브젝트 유형별 결과를 실행한다.

### 현재 대상 유형

| 유형 | 도착 후 행동 |
|---|---|
| 아이템 획득 오브젝트 | 고유 아이템을 인벤토리에 추가하고 월드 오브젝트를 소모 처리한다. |
| 방 이동용 문 | 잠금 상태를 확인하고, 사용 가능하면 문을 열거나 통과 행동을 시작한다. |
| 아이템 사용 대상 | 아이템 선택 UI를 열고 플레이어의 선택을 기다린다. |
| 은신처 | 은신 가능 여부를 확인하고 은신 상태로 전환한다. |
| 퍼즐 대상 | 해당 퍼즐 UI를 열거나 퍼즐 행동을 시작한다. |

### 아이템 사용

- 플레이어가 대상에 접근한 뒤 보유 아이템 목록에서 사용할 아이템을 직접 선택한다.
- 올바른 아이템이면 대상 효과를 실행하고 사용한 아이템을 제거한다.
- 올바르지 않은 아이템이면 사용할 수 없다는 메시지를 표시하고 아이템은 유지한다.
- 잠긴 문도 아이템 사용 대상이 될 수 있다.

### 후속 기획

- 스테이지별 실제 상호작용 오브젝트 목록
- 각 대상에 사용할 수 있는 아이템과 성공 효과
- 퍼즐의 종류, UI, 성공·실패 규칙

## 5. 인벤토리

### 책임

- 고유 아이템의 보유 여부를 기록한다.
- Tab 입력 또는 아이템 사용 요청 시 아이템 목록 UI를 표시한다.
- 사용 완료된 아이템을 제거한다.
- 체크포인트 복원 시 지정된 아이템 목록으로 교체한다.

### 확정 사양

- 모든 아이템은 고유 아이템이며 수량과 중첩을 지원하지 않는다.
- 아이템 조합, 정렬, 장비 슬롯은 구현하지 않는다.
- 사용할 아이템은 플레이어가 직접 선택한다.
- 사용한 아이템은 스토리 진행에 맞게 인벤토리에서 제거한다.
- 인벤토리 UI가 게임을 멈춰야 할 경우 Core의 공용 일시정지를 사용한다.

### 후속 기획

- Tab 인벤토리 UI의 최종 배치
- 아이템 설명과 이미지
- Tab 인벤토리 표시 중 실제 일시정지 적용 여부

## 6. 적 순찰과 스토리 적

### 책임

- 맵별 목적지 목록에 따라 적을 이동시킨다.
- 각 목적지의 방 ID를 바탕으로 현재 방과 다음 목적지 방을 알린다.
- 플레이어 진행에 따라 활성 순찰 경로를 교체한다.
- 스토리 이벤트 요청에 따라 일반 순찰 적과 스토리용 적을 활성화·비활성화한다.

### 최소 상태

- `Patrolling`: 지정 목적지로 이동
- `Waiting`: 목적지에서 짧게 대기
- `Chasing`: 같은 방의 노출된 플레이어를 향해 이동
- `Inactive`: 스토리상 비활성화

별도의 스토리용 적도 같은 이동 컴포넌트를 사용하되 지정 위치와 지정 시점에서 활성화한다.

### 확정 사양

- 순찰 경로는 목적지 목록으로 정의하며 맵별로 순환 또는 왕복을 선택할 수 있다.
- 목적지별 대기 시간은 단순한 설정값으로 둔다.
- 플레이어 진행에 따라 다른 목적지 목록으로 교체할 수 있다.
- 적은 닫힌 문을 열고 이동할 수 있다.
- 스토리 이벤트는 기존 순찰 적을 잠시 비활성화하고 별도의 스토리용 적을 지정 위치에서 활성화할 수 있다.

### 후속 기획

- 맵별 목적지 목록과 순환·왕복 방식
- 진행 단계별 경로 교체 시점
- 이동 속도와 대기 시간
- 적이 문을 여는 애니메이션과 통과 타이밍

## 7. 위험 경보

### 책임

적 순찰 시스템의 현재 방과 다음 목적지로부터 경보를 계산하고 UI와 사운드에 전달한다.

### 경보 규칙

| 상태 | 표시 |
|---|---|
| 적이 문 하나로 연결된 인접 방에 있음 | 주의 경보 |
| 적의 다음 목적지가 플레이어의 현재 방으로 결정됨 | 긴급 경보 |
| 적이 플레이어의 현재 방에 진입함 | 긴급 경보 유지 |
| 위 조건에 해당하지 않음 | 경보 없음 |

### 확정 사양

- 기존 1단계 경보는 사용하지 않는다.
- 긴급 경보는 적이 다음 목적지를 결정한 순간 시작한다.
- 적이 현재 방에 진입한 이후에도 포획 상황이 끝날 때까지 긴급 경보를 유지한다.
- UI는 화면 중앙 상단에 표시하며 이동 및 상호작용 중에도 숨기지 않는다.
- 경보 변경과 함께 사운드를 재생한다.

### 후속 기획

- 경보 단계의 명칭
- 아이콘, 색상, 애니메이션과 사운드
- 은신 중 경보 종료 시점

## 8. 은신·포획·사망·추격

### 은신

- 은신처 클릭도 일반 `TargetCommand`로 실행한다.
- 플레이어가 은신처 접근 지점에 도착한 뒤에만 은신 상태가 된다.
- 도착 전에 적이 현재 방에 진입하면 도착하더라도 은신 상태로 전환하지 않는다.
- 은신 중에는 일반 클릭 대상을 모두 숨기고 오른쪽 아래의 은신 해제 버튼만 활성화한다.
- 은신 해제 버튼을 누르면 플레이어가 은신처 바로 앞으로 나온다.

### 포획과 사망

- 같은 방에 진입한 적은 은신하지 못한 플레이어를 향해 이동한다.
- 적이 플레이어와 접촉하면 짧은 포획 애니메이션을 재생한 뒤 사망 처리한다.
- 사망 후 Core에 현재 체크포인트 복원을 요청한다.
- 복원 시 플레이어와 진행 상태는 체크포인트 정의를 따르고 적은 지정 초기 위치로 돌아간다.

### 미확정: 추격

- 일반 명령과 달리 이동 중 다음 지점 클릭을 허용할 수 있다.
- 목표 즉시 변경, 다음 목표 예약, 포획 거리, 성공 지점 등은 추격 장면 기획에서 확정한다.

## 시스템 의존 관계

```text
스토리 진행 Core / 체크포인트
        ├─ 인벤토리·진행 상태 복원
        ├─ 적 초기화 및 경로 교체
        └─ 공용 일시정지

방·문·CCTV
        ├─ TargetCommand의 이동 범위와 카메라 전환
        ├─ 적의 현재 방 및 목적지 방
        └─ 위험 경보의 인접 방 판정

TargetCommand
        └─ 오브젝트 상호작용
                ├─ 인벤토리
                ├─ 방 이동
                ├─ 퍼즐
                └─ 은신

적 순찰
        ├─ 위험 경보
        └─ 은신 실패·포획
```

## 구현 순서

1. 방 ID, 직접 인접 정보, 문 통과 지점과 CCTV 전환
2. 단일 `TargetCommand`와 명령 중 클릭 UI 차단
3. 아이템 획득, 문, 아이템 사용 대상의 공통 상호작용
4. 고유 아이템 인벤토리와 아이템 선택 UI
5. 고정 목적지 목록 기반 적 순찰과 진행 단계별 경로 교체
6. 주의·긴급 위험 경보 UI와 사운드 연결
7. 은신, 은신 실패, 적 접근, 포획과 사망
8. 메모리 체크포인트와 지정 상태 복원
9. 스테이지 기획에 따른 퍼즐
